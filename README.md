# SNS Post

記事を公開したら、Bluesky・Threads・X・Facebook ページ・Discord へ自動で投稿する WordPress プラグインです。フォームの送信やコメントも Discord に知らせます。

仲介するサービスを通さず、サイトから各 SNS の API へ直接送ります。サイトのデータや SNS の権限を、ほかのサービスに預けずに済みます。

## できること

| | Bluesky | Threads | X | Facebook ページ |
|---|---|---|---|---|
| リンクのカード | ○（アイキャッチ画像つき） | ○ | ○ | ○ |
| ハッシュタグ・URL のリンク | ○ | ○（トピックになるタグは1つだけ） | ○ | ○ |
| 文字数の上限 | 300（超えた分は切る） | 500（超えた分は切る） | 280（全角は2、URL は23と数える。超えた分は切る） | なし |
| つなぎ方 | アプリパスワード | ログインしてつなぐ（トークンは毎週自動で延長） | 開発者コンソールの4つの鍵（期限なし） | ログインしてつなぐ（ページのトークンは期限なし） |
| 料金 | 無料 | 無料 | **有料**（API の従量課金。リンク付きの投稿は1件ごとにかかる） | 無料 |

- 記事の編集画面の右側「SNS 投稿」で、記事ごとに投稿文を書けます。空なら記事のタイトルを投稿します
- 「この記事は SNS に投稿しない」も選べます
- 公開から約1分後に WP-Cron で送ります。更新しただけでは送りません
- 失敗したら10分おきに3回まで試します。だめなら記事の画面に理由が出て、「今すぐ送る」でやり直せます
- あきらめた投稿や、Threads のトークンを延ばせなくなったことを Discord に知らせます
- テストモードでは、実際には送らずにログに残すだけにできます

## Discord

チャンネルの「設定 → 連携サービス → ウェブフック」で作った URL を、設定画面の Discord のタブに入れます。

| 用途 | いつ送るか |
|---|---|
| 記事の公開 | 送り先で Discord にチェックを入れたとき。ほかの SNS と同じく、公開から約1分後に送る（テストモードの間は送らない） |
| フォームの送信 | フォームのプラグインが下のフックを呼んだとき |
| コメント | コメントが入ったとき（スパム・ゴミ箱は除く） |
| SNS 投稿の失敗・トークンの期限 | 投稿をあきらめたとき、Threads のトークンを延ばせなくなったとき |

- 用途ごとに送り先を分けられます。空の用途は「ふだんの送り先」へ送ります
- 1行に1つ書けば、複数のチャンネルへ送ります
- 本文に `@everyone` / `@here` / `<@ユーザーID>` があっても、メンションの通知は飛びません
- 保存した URL は、画面では末尾の4文字だけ見せます

### フォームから知らせる

送信が済んだところで次のフックを呼ぶと、「フォームの送信」の送り先へ送ります。[Contact Inbox](https://github.com/donnma777/wp-contact-inbox) は対応済みです。

```php
do_action( 'dsp_form_submitted', 'お問い合わせ', array(
	'お名前'         => $name,
	'メッセージ本文' => $body,
) );
```

## インストール

1. [Releases](https://github.com/donnma777/wp-sns-post/releases) から zip をダウンロード
2. 管理画面「プラグイン → 新規追加 → プラグインのアップロード」で zip を選んで有効化
3. 「設定 → SNS 投稿」の Bluesky・Threads・X・Facebook・Discord のタブでそれぞれつなぎ、「確かめる」で確認
4. 「基本」のタブで送り先にチェックを入れて、テストモードを外す

入れたばかりのときはテストモードで、どこにも送りません。ほかの自動投稿のプラグインから乗り換えるときは、そちらを止めてからテストモードを外してください（同じ記事が二重に投稿されます）。

## SNS とつなぐ

### Bluesky

Bluesky の「設定 → プライバシーとセキュリティ → アプリパスワード」でアプリパスワードを作り、Bluesky のタブで ID（example.bsky.social など）と一緒に入れます。ダイレクトメッセージへのアクセスは許可しなくてかまいません（投稿にしか使いません）。

### X

X の API は従量課金です。先に開発者コンソールでクレジットを買っておかないと、投稿が失敗します（料金は開発者コンソールで確かめてください）。

1. [X の開発者コンソール](https://console.x.com/)でアプリを作る
2. アプリの「User authentication settings」で、権限（App permissions）を「Read and write」にする
3. 「Keys and tokens」で API キー（Consumer Key）とシークレット、「Access Token and Secret」を作る。**権限を変えたあとに作ったアクセストークンでないと、投稿できません**
4. 設定画面の X のタブに4つを入れて保存する（保存すると、つながるか確かめてアカウント名を出します）

鍵に期限はありません。投稿はアプリを作ったアカウントからになります。「確かめる」は、そのたびに読み取りの料金が少しかかります。

### Threads と Facebook ページ（1つの Meta アプリでログインしてつなぐ）

Threads と Facebook は、1つの Meta アプリを作っておけば、設定画面のボタンからログインしてつなげます。トークンをコピーして貼る必要はありません。

**アプリを作る（最初の1回だけ）**

1. [Meta for Developers](https://developers.facebook.com/apps/) でアプリを作る。ユースケースは「Threads API」と「ページのすべてを管理」の2つを選ぶ（ユースケースはあとから外せません）
2. Threads API のユースケースで、権限 `threads_basic` と `threads_content_publish` を足す
3. ページの管理のユースケースで、権限 `pages_show_list`・`pages_read_engagement`・`pages_manage_posts` を足す
4. 設定画面の Threads・Facebook のタブに出ている**戻り先の URL**（`https://<サイト>/wp-admin/admin-post.php`）を、次の2か所に登録する
   - Threads API の設定 →「コールバック URL」（リダイレクト用）
   - Facebook ログイン（for Business）の設定 →「有効な OAuth リダイレクト URI」
5. 「アプリの役割 → 役割」で、自分の Threads アカウントを Threads テスターに足す。Threads の「設定 → アカウント → ウェブサイトのアクセス許可 → 招待」で承認する
6. 「アプリ設定 → ベーシック」で、プライバシーポリシーの URL などを入れる

**つなぐ**

1. 「アプリ設定 → ベーシック」には ID とシークレットが**2組**あります（上が Facebook 用、下のほうが Threads 用）。それぞれのタブで使う
2. Threads のタブで、Threads のアプリ ID とシークレットを入れ、「Threads にログインしてつなぐ」
3. Facebook のタブで、Facebook のアプリ ID とシークレットを入れ、「Facebook にログインしてつなぐ」。ページが複数あれば、戻ってきた画面で選ぶ

アプリシークレットは、つなぐときに使うだけで保存しません（ログインの途中だけ、暗号化して10分置きます）。

- Threads：トークンの期限は60日で、プラグインが毎週延ばします。サイトに60日アクセスがないと WP-Cron が動かず、期限が切れます。そのときは「つなぎ直す」を押します
- Facebook：期限のないページのトークンに替えて保存します
- 自分のアカウント・自分のページに投稿するだけなら、アプリの審査は要りません
- **Facebook は、アプリが開発モードのままだと、投稿がアプリの管理者にしか見えないことがあります。** 最初の投稿をほかの人（ログアウトした状態）から見て、見えなければアプリを「公開（ライブ）」に切り替えてください
- ログインで「権限が無効」などと出るときは、Facebook ログイン for Business で権限をまとめた「設定」を作り、その設定 ID を設定画面に入れます

ログインがうまくいかないときは、各欄の「トークンを手で入れる」からもつなげます（Threads はユーザートークン生成ツールのトークン、Facebook はグラフ API エクスプローラのユーザートークン）。

### wp-config.php で指定する（任意）

データベースにトークンを置きたくないときは、`wp-config.php` に書けます。管理画面の値より優先します。

```php
define( 'DSP_BLUESKY_IDENTIFIER', 'example.bsky.social' );
define( 'DSP_BLUESKY_APP_PASSWORD', 'xxxx-xxxx-xxxx-xxxx' );
define( 'DSP_X_API_KEY', '...' );
define( 'DSP_X_API_SECRET', '...' );
define( 'DSP_X_ACCESS_TOKEN', '...' );
define( 'DSP_X_ACCESS_SECRET', '...' );
define( 'DSP_FACEBOOK_PAGE_ID', '123456789' );
define( 'DSP_FACEBOOK_PAGE_TOKEN', 'EAAB...' );
```

Discord の Webhook も書けます（すべての用途でこの URL を使います）。

```php
define( 'DSP_DISCORD_WEBHOOK_URL', 'https://discord.com/api/webhooks/xxxx/yyyy' );
```

Threads のトークンは自動で延ばすため、データベースに置きます。アプリシークレットも定数で書けます（書けば、つなぐときに入れなくて済みます）。

```php
define( 'DSP_META_APP_SECRET', '...' );    // Facebook 用
define( 'DSP_THREADS_APP_SECRET', '...' ); // Threads 用
```

## フィルター

| フィルター | 用途 |
|---|---|
| `dsp_post_types` | 送る投稿タイプ（初めは `post` だけ） |
| `dsp_content` | 投稿の中身（本文・タイトル・URL・説明文）を変える |

| アクション | 用途 |
|---|---|
| `dsp_form_submitted` | フォームの送信を Discord に知らせる（フォーム名, 項目名 => 値 の配列） |

## 動作環境

- WordPress 6.6 以上（ブロックエディター）
- PHP 7.4 以上

## 注意

- トークンはサイトのデータベース（`wp_options`、autoload なし）に置きます。サイトそのものが破られると漏れるので、使わなくなったら SNS 側でも取り消してください
- プラグインを削除すると、設定とログを消します
- 個人で作ったものです。サポートや不具合対応のお約束はできません
